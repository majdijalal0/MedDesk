## Overview

MedDesk digitizes the daily workflow of a medical office: patient record management, secretary-doctor collaboration, and AI-assisted clinical note organization — all while keeping a human in the loop for anything AI-generated.


## Features

-  Role-based access for **Médecin**, **Secrétaire**, and **Administrateur**
-  Doctor-secretary assignment system supporting many-to-many relationships
-  AI-assisted patient note organization and résumé generation (Gemini API)
-  Human-in-the-loop (HITL) validation workflow for all AI-generated content
-  Structured, flexible medical record storage (JSONB)
-  Soft-delete for medical data retention and auditability

## Architecture

MedDesk follows a classic three-tier architecture, with an external AI service integrated into the backend for note processing.



## Authentication & Role-Based Access Control

MedDesk enforces three distinct roles at the API level via route guards:

- **Médecin** — full clinical access to their assigned patients
- **Secrétaire** — administrative access, can act on behalf of an assigned doctor
- **Administrateur** — scoped strictly to user account management, with **no access to clinical data**

A `resolveDoctorId` abstraction handles the secretary-acting-on-behalf-of-doctor pattern consistently across controllers.



## AI-Assisted Note Generation

Clinical notes and patient résumés are generated using the Gemini API, with prompting designed to minimize hallucination (explicit "Non renseigné" fallback for missing data, and Markdown suppression for clean plain-text output).

Every AI-generated note goes through a **human-in-the-loop validation workflow** before it's saved — doctors can **Valider**, **Éditer**, or **Rejeter** any AI output. Nothing generated by the AI is persisted without explicit human review.



## Data Model Highlights

- `informations_medicales` stored as JSONB for flexible, evolvable medical record structure
- `SecretaryAssignments` join table manages many-to-many doctor-secretary relationships, with UNIQUE constraints to prevent race conditions and transactions for atomic operations
- Soft-delete pattern applied to medical data to preserve historical records



## Getting Started

```bash
# Clone the repository
git clone https://github.com/your-username/meddesk.git
cd meddesk

# Install backend dependencies
cd backend
npm install

# Install frontend dependencies
cd ../frontend
npm install

# Set up environment variables
cp .env.example .env
# Fill in DATABASE_URL, JWT_SECRET, GEMINI_API_KEY, etc.

# Run the backend
cd ../backend
npm run dev

# Run the frontend
cd ../frontend
npm run dev
```

## Known Limitations

- Testing is currently entirely manual (via Postman).
- JWT cookies are flagged `secure: false`, which should be updated to `true` in a production HTTPS environment
- Built and validated primarily in a single-institution context; broader deployment would require further hardening
